# dsh-1c-project-properties

**Параметры 1С в разрезе проекта внутри DeepSeek Harness.**

Отдельная вкладка **«1С: параметры»** в настройках DSH: общие значения для машины, список проектов и форма параметров выбранного проекта. Значения проекта лежат в его собственной папке — в файле `.dsh/1c-project.json`, поэтому переезжают вместе с проектом, видны в git и доступны другим инструментам.

## Возможности

### ⚙️ Вкладка «1С: параметры» в настройках DSH
Секция в Settings — рядом с «Основные» и «Плагины». Внутри: блок общих значений, список проектов слева, форма параметров справа.

### 📁 Значения живут в папке проекта
Файл `.dsh/1c-project.json` в корне проекта: путь к базе, пользователь, пароль, путь к платформе. Запись атомарная (временный файл + переименование), посторонние ключи в файле сохраняются, кодировка UTF-8. Файл можно править руками — плагин подхватит значения при следующем открытии вкладки.

### 🧩 Путь к платформе: общее значение и переопределение
В общих настройках задаётся путь к платформе по умолчанию. В проекте поле можно оставить пустым — тогда берётся общее значение; своё значение перекрывает общее. Действующий путь всегда виден в форме проекта.

### 🔎 Автопоиск установленных платформ
Хост-часть сканирует `%ProgramFiles%\1cv8`, `%ProgramFiles(x86)%\1cv8` и `%LOCALAPPDATA%\Programs\1cv8`, собирает версии с `bin\1cv8.exe` и отдаёт их в поле ввода как список автодополнения. Ничего не нашлось — путь вводится руками.

### 🗂 Проекты = воркспейсы DSH плюс добавленные вручную
Список берётся из реестра воркспейсов DSH (`ctx.workspaceRegistry`), а не из рабочего каталога процесса. Папку, не зарегистрированную как воркспейс, можно добавить во вкладке — путь сохранится, параметры будут лежать в ней же. Метка ● у проекта означает, что файл параметров уже есть, ○ — ещё нет.

### ⤓ Выгрузка конфигурации в файлы
Кнопка **«Выгрузить конфигурацию в файлы»** запускает Конфигуратор 1С в пакетном режиме (`DESIGNER /DumpConfigToFiles`) и складывает XML прямо в папку проекта — рядом появляются `Configuration.xml`, `ConfigDumpInfo.xml` и каталоги объектов. Доступны формат выгрузки (иерархический/плоский), режим `-update` (только изменившиеся объекты) и снятие lock-файлов `.cfl`. Прогресс, время, число файлов, версия конфигурации и лог Конфигуратора показываются в той же вкладке; выгрузку можно отменить.

### 🔌 Роуты `/1cprops/*` для других плагинов и агентов
Вся работа идёт через хост-роуты, ими же можно пользоваться снаружи: `GET /1cprops/project?path=…` отдаёт действующие параметры проекта с уже подставленным путём к платформе.

## Параметры

| Поле | Ключ в JSON | Значение |
|---|---|---|
| Путь к базе | `infobasePath` | папка файловой базы либо строка соединения `Srvr="srv";Ref="base";` |
| Пользователь | `user` | имя пользователя 1С |
| Пароль | `password` | пароль авторизации |
| Путь к платформе | `platformPath` | `…\bin\1cv8.exe`; пусто — берётся общее значение |
| Код доступа к базе | `unlockCode` | код для обхода блокировки установки соединений (`/UC`); пусто — не передаётся |
| Каталог выгрузки | `dumpDir` | куда писать XML; пусто — корень проекта |

Общие значения хранятся на машину: `$DSH_HOME/1c-project-properties/settings.json` (`$DSH_HOME` — переменная окружения, иначе `~/.dsh`).

## Использование

1. Откройте **Settings → «1С: параметры»**.
2. В блоке **«Общие»** укажите путь к платформе по умолчанию — он подставляется во все проекты, где поле не заполнено.
3. Выберите проект в списке слева. Воркспейсы DSH попадают туда сами; папку без воркспейса добавьте полем под списком.
4. Заполните путь к базе, пользователя и пароль, нажмите **«Сохранить»** — рядом с проектом появится `.dsh/1c-project.json`.
5. Путь к платформе в проекте задавайте, только если он отличается от общего. Кнопка **«Удалить файл»** убирает параметры проекта, **«Убрать из списка»** — убирает добавленный вручную путь.
6. Для выгрузки: проверьте **«Каталог выгрузки»** (пусто = корень проекта), выберите формат и нажмите **«Выгрузить конфигурацию в файлы»**. Идёт одна выгрузка за раз — Конфигуратор блокирует конфигурацию базы.
7. По завершении вкладка покажет число файлов, версию конфигурации и лог Конфигуратора. Если в базе остались lock-файлы `.cfl`, включите одноимённую галочку — иначе выгрузка завершится ошибкой блокировки.

## Установка

Нужен `dsh` ≥ 0.1.2-rc.1. Ставится тремя способами — результат один и тот же.

**Из релиза** (скачивать ничего не нужно):

```sh
dsh plugin --profile web add https://github.com/Mempemp/DSH-1CProjectProperties/releases/download/v0.2.0/dsh-1c-project-properties-0.2.0.tgz
```

**Локальный архив** `dsh-1c-project-properties-0.2.0.tgz` (скачан со страницы релизов или собран самому: `cd dsh-1c-project-properties && npm pack`):

```sh
dsh plugin --profile web add dsh-1c-project-properties-0.2.0.tgz
```

**Папка плагина** (режим разработки, правки в `lib/*.js` подхватываются без переустановки):

```sh
dsh plugin --profile web add <путь к папке>/dsh-1c-project-properties
```

После установки перезапустите DSH (композиция плагинов читается на старте) и обновите страницу в браузере.

### Если `dsh` не в PATH

Локальная установка и DSH Desktop не добавляют `dsh` в `PATH` — вызывайте точку входа через node. Путь к `bin.js`:

| Как установлен DSH | Путь к `bin.js` |
|---|---|
| локально (`npm install @deepseek-ai/dsh`) | `<папка установки>\node_modules\@deepseek-ai\dsh\lib\bin.js` |
| DSH Desktop | `%LOCALAPPDATA%\Programs\DSH Desktop\resources\app\node_modules\@deepseek-ai\dsh\lib\bin.js` |

```powershell
node "C:\путь\к\dsh\lib\bin.js" plugin --profile web add "C:\путь\к\dsh-1c-project-properties-0.2.0.tgz"
```

### Возможные сложности

| Симптом | Что делать |
|---|---|
| `ERR_PNPM_UNEXPECTED_STORE` | добавить `--store-dir="<путь к вашему pnpm store>"` к команде установки |
| `EPERM` при записи в `…\profiles\web` | нет прав на папку профиля (песочница, антивирус): закрыть DSH, разрешить запись, повторить |
| Предупреждения про peer-зависимости (`cordis`, `react`, `react-dom`) | игнорировать: внешних зависимостей у плагина нет, react приходит из рантайма DSH |
| Путь к архиву содержит пробелы | ломается на `.cmd`-шиме pnpm — положите архив в путь без пробелов или поставьте папкой |
| После установки в `dsh.profile.bundles` появились лишние пакеты | `dsh plugin add` перезаписывает список слоёв: плагины, которые `dshmarket` держал «горячими» (`.dsh-market\hot-*.yml`), получают постоянную активацию. Ненужные строки можно удалить из `package.json` профиля, на работу плагина это не влияет |
| Вкладки нет после установки | DSH не перезапущен либо страница не перезагружена жёстко (`Ctrl+Shift+R`) |
| Выгрузка: «Ошибка блокировки информационной базы для конфигурирования» | в каталоге файловой базы остались lock-файлы `.cfl` — включите галочку **«снять .cfl перед выгрузкой»** (или закройте чужую сессию Конфигуратора) |
| Выгрузка: «Информационная база не обнаружена!» | неверный путь к базе: путь к папке с `1Cv8.1CD` либо строка `Srvr="…";Ref="…";` |
| Выгрузка мгновенно завершается «успешно», файлов 0 | указан `1cv8s.exe` (серверный агент) — в сессии пользователя он молча ничего не делает. Укажите `1cv8.exe` из того же `bin` |
| Выгрузка не стартует, если указан только каталог платформы | плагин сам ищет `1cv8.exe` в каталоге и в его `bin` — дайте либо файл, либо папку |

Проверка, что хост-часть поднялась: `curl -s http://127.0.0.1:<порт>/1cprops/state` — должен вернуться JSON со списком проектов.

## Требования

- DeepSeek Harness (`dsh web` или DSH Desktop) ≥ 0.1.2-rc.1 — вкладка использует слот `settings.section`
- Node.js ≥ 20
- Платформа 1С:Предприятие 8.3 — только для кнопки выгрузки; путь задаётся в параметрах (`1cv8.exe` или каталог `bin`)

## HTTP-роуты

| Метод и путь | Назначение |
|---|---|
| `GET /1cprops/state` | общие настройки, список проектов, найденные платформы 1С |
| `POST /1cprops/common` | `{platformPath}` — сохранить общее значение |
| `POST /1cprops/project-save` | `{path, params}` — записать файл параметров проекта |
| `GET /1cprops/project?path=…` | действующие параметры проекта (общий путь к платформе подставлен) |
| `POST /1cprops/project-clear` | `{path}` — удалить файл параметров |
| `POST /1cprops/project-add` | `{path}` — добавить папку в список проектов |
| `POST /1cprops/project-forget` | `{path}` — убрать дополнительный путь из списка |
| `POST /1cprops/dump-start` | `{path, dir?, format?, update?, cleanLocks?}` — запустить выгрузку конфигурации (202, 409 если уже идёт) |
| `GET /1cprops/dump-status` | состояние выгрузки: `state`, время, файлы, версия конфигурации, лог Конфигуратора |
| `POST /1cprops/dump-cancel` | остановить выгрузку (убивает дерево процессов 1С) |

Логи и результаты выгрузки хост-часть складывает в `$DSH_HOME/1c-project-properties/jobs`.

## Структура репозитория

- `dsh-1c-project-properties/lib/index.js` — host-часть (ESM): роуты `/1cprops/*`, чтение и запись JSON, поиск установленных платформ 1С, запуск Конфигуратора в пакетном режиме.
- `dsh-1c-project-properties/lib/client.js` — клиентская часть: секция `settings.section` («1С: параметры») со списком проектов и формой.
- `dsh-1c-project-properties/cordis.patch.yml` — строка монтирования плагина в композицию профиля.
- `dsh-1c-project-properties/README.md` — описание пакета (то же, что и в архиве релиза).

Внешних зависимостей нет: только `node:*` и React из рантайма DSH.

## Безопасность

Пароль хранится в файле проекта открытым текстом — не коммитьте `.dsh/1c-project.json` в репозитории проектов. Хост-роуты доступны локально без токена сессии (как и роуты других плагинов через `ctx.webServer.register`); сервер DSH слушает `127.0.0.1`.
