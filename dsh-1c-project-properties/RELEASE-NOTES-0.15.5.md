# 0.15.5 — переход со старых правил без вопросов

Повторное развёртывание поверх проекта со старыми правилами проверено на живых прогонах.

## Что происходит при повторном «Развернуть правила»

- Плейбуки, которые не менялись (нашли, платформа, ИТС, база, метаданные, правка модуля,
  ревью), остаются байт в байт — лишней правки в git нет.
- Изменённые (`code.md`, `metadata.md`, `ui.md`) заменяются новой версией.
- Новые (`query.md`, `reports.md`) добавляются.
- `AGENTS.md` пересобирается из новой шапки, `USER-RULES.md` не трогается,
  `environment.md` и `.dsh/1c-rules.json` обновляются.
- Отчёт в карточке показывает, что записано и что оставлено.

## Если вы правили плейбук сами

Файл остаётся вашим: новые разделы в него не приезжают. В отчёте это видно строкой
«Оставлено ваше». Добавлена подсказка, что с этим делать: удалить файл и развернуть снова —
вернётся свежая версия. Проверено: файл с правкой сохраняется, после удаления приходит новая
версия.

## Если в проекте было дерево comol

Файлы остаются на диске целиком (`.dsh/rules-1c/`, `.dsh/agents-1c/`, `.dsh/commands-1c/`,
`.dsh/skills/` — 106 файлов в проверке), но карта comol больше не входит в `AGENTS.md`:
она ведёт на MCP-серверы, которых в этой сборке нет. Раньше это происходило молча — теперь
в отчёте есть строка «дерево comol в проекте осталось без изменений; в AGENTS.md его карта
не включена».

## Проверено

Три живых прогона на временных проектах: (1) старые правила → новые: 2 файла добавлено,
5 изменено, 8 без изменений, предупреждений нет; (2) правка пользователя в `code.md`:
сохранена, новых разделов нет, в отчёте `preserved`; после удаления файла — записана новая
версия; (3) старые правила с включённым comol → новые без comol: дерево на диске целое,
блок из `AGENTS.md` убран, в отчёте появилась строка про comol. `test/rules-deploy.smoke.mjs`
— 49 проверок.
