# dsh-1c-project-properties

**Параметры 1С в разрезе проекта внутри DeepSeek Harness.**

Отдельная вкладка **«1С: Параметры проектов»** в настройках DSH: общие значения для машины, список проектов и форма параметров выбранного проекта. Значения проекта лежат в его собственной папке — в файле `.dsh/1c-project.json`, поэтому переезжают вместе с проектом, видны в git и доступны другим инструментам.

## Возможности

### ⚙️ Вкладка «1С: Параметры проектов» в настройках DSH
Секция в Settings — рядом с «Основные» и «Плагины». Внутри: карточка общих значений для машины и список проектов (название, путь, точка «файл параметров есть»). Параметры проекта открываются в отдельном окне — по клику на проект: колонка настроек шириной около 520 px, в неё форма не помещалась.

Окно параметров собрано из трёх карточек: **«Подключение»** (данные базы), **«Выгрузка и загрузка конфигурации»** (операции Конфигуратора), **«Правила 1С в проекте»**. Шапка и подвал закреплены, прокручивается только содержимое; технические ключи команд не выносятся в подписи (они в подсказках при наведении), а длинные пояснения свёрнуты в раскрывающиеся блоки. Отказы операций и развёртывания показываются в тех же карточках, где нажата кнопка.

Скриншоты предыдущей версии интерфейса — в v0.5.0 окно параметров переработано (карточки-секции, закреплённые шапка и подвал):

### 🧠 Платформенный контекст 1С (MCP)

Плагин поднимает рядом с DSH локальный MCP-сервер справки по API платформы и
отдаёт его MCP-менеджеру: агент получает инструменты
`mcp__1c-platform-context__*` — поиск по типам, методам, свойствам,
конструкторам и значениям системных перечислений, проверку числа аргументов
глобальных функций и валидацию BSL-кода против установленной версии платформы.

Сервер читает синтакс-помощник (`shcntx_ru.hbk`) той версии платформы, путь к
которой задан в общих значениях, — справка всегда соответствует установленной
платформе, интернет не нужен. Пока путь не задан, сервер **не поднимается
вовсе** — незачем держать процесс и индекс в памяти ради инструментов, которых
не будет; состояние и причина видны в карточке «Платформенный контекст (MCP)».
Как только путь указан, сервер стартует сам; очистка пути его гасит.

### 📜 Правила 1С в проекте
Набор [1c-rules](https://github.com/comol/ai_rules_1c) раскладывается в проект одной кнопкой **«Развернуть»** — в ту структуру, которую читает DSH:

| Что | Куда |
|---|---|
| Правила (48 файлов) | `.dsh/rules-1c/` — читаются по ссылкам |
| Роли субагентов (13) | `.dsh/agents-1c/` |
| Сценарии-команды (30) | `.dsh/commands-1c/` |
| Навыки (12 + 4 OpenSpec) | `.dsh/skills/` — DSH видит их как проектные |
| Точка входа (always-on контекст) | `AGENTS.md` в корне проекта |
| Параметры для правил | `.dev.env` из `.dsh/1c-project.json` |
| Workspace OpenSpec | `openspec/` (skip-if-exists) |

Ссылки внутри правил написаны под раскладку репозитория-источника (`content/rules/…`, `content/agents/…`, `content/commands/…`, `content/skills/…`) и при развёртывании переписываются на проектные — иначе агент получил бы указатели в никуда. Рядом кладётся сгенерированный `.dsh/rules-1c/dsh-environment.md`: где что лежит, какие MCP-серверы из ожидаемых правилами реально установлены, и чем механика DSH отличается от хостов, под которые правила писались (нет markdown-субагентов, нет проектных slash-команд, `USER-RULES.md` не загружается сам).

Развёртывание идемпотентно и не разрушительно:

- существующий `AGENTS.md` не затирается: он сохраняется как `AGENTS.md.bak.md` и вклеивается в `USER-RULES.md` между маркерами (штатное поведение 1c-rules);
- `.dev.env`, `openspec/`, `USER-RULES.md`, `memory.md`, `LLM-RULES.md` создаются один раз и дальше не трогаются;
- правки пользователя в развёрнутых файлах сохраняются: файл с изменённым содержимым не перезаписывается и остаётся при удалении правил;
- повторное нажатие не переписывает ничего лишнего (в отчёте — «без изменений»).

Плагин не следит за версией набора и за состоянием развёртывания в проекте. Проверяется ровно одно: есть ли набор в `$DSH_HOME/1c-rules`. Набора нет — карточка говорит об этом и кнопка заблокирована: в standalone-установке набор в этот каталог нужно положить самому (его кладёт DSH Desktop при первом запуске). Отчёт развёртывания, включая отказ с текстом ошибки, показывается в самой карточке.

Пароль базы в `.dev.env` по умолчанию **не** переносится (`.dev.env` часто попадает в git) — включается отдельной галочкой.

### 📁 Значения живут в папке проекта
Файл `.dsh/1c-project.json` в корне проекта: путь к базе, пользователь, пароль, путь к платформе. Запись атомарная (временный файл + переименование), посторонние ключи в файле сохраняются, кодировка UTF-8. Файл можно править руками — плагин подхватит значения при следующем открытии вкладки.

### 🧩 Путь к платформе: общее значение и переопределение
В общих настройках задаётся путь к платформе по умолчанию. В проекте поле можно оставить пустым — тогда берётся общее значение; своё значение перекрывает общее. Действующий путь всегда виден в форме проекта.

### 🔎 Автопоиск установленных платформ
Хост-часть сканирует `%ProgramFiles%\1cv8`, `%ProgramFiles(x86)%\1cv8` и `%LOCALAPPDATA%\Programs\1cv8`, собирает версии с `bin\1cv8.exe` и отдаёт их в поле ввода как список автодополнения. Ничего не нашлось — путь вводится руками.

### 🗂 Проекты = воркспейсы DSH плюс добавленные вручную
Список берётся из реестра воркспейсов DSH (`ctx.workspaceRegistry`), а не из рабочего каталога процесса. Папку, не зарегистрированную как воркспейс, можно добавить во вкладке — путь сохранится, параметры будут лежать в ней же. Метка ● у проекта означает, что файл параметров уже есть, ○ — ещё нет.

### ⤓ Выгрузка конфигурации в файлы
Кнопка **«Выгрузить конфигурацию в файлы»** запускает Конфигуратор 1С в пакетном режиме (`DESIGNER /DumpConfigToFiles`) и складывает XML прямо в папку проекта — рядом появляются `Configuration.xml`, `ConfigDumpInfo.xml` и каталоги объектов. Доступны формат выгрузки (иерархический/плоский), режим `-update` (только изменившиеся объекты) и снятие lock-файлов `.cfl`. Прогресс, время, число файлов, версия конфигурации и лог Конфигуратора показываются в той же вкладке; выгрузку можно отменить.

Состояние операции вынесено в отдельный блок с рамкой: заголовок («Операция идёт / завершена / не удалась / отменена») и тип операции, метрики «Время», «Файлов», «Версия», каталог выгрузки и причина — если операция провалилась. Пока операция не сброшена, такой же блок виден на главной вкладке с кнопками **«Открыть»** и **«Отменить»**.

### ⇧ Загрузка конфигурации из файлов в базу
Кнопка **«Загрузить конфигурацию из файлов»** выполняет обратную операцию: `DESIGNER /LoadConfigFromFiles <каталог> -Format <формат>` и, если включена галочка, `/UpdateDBCfg` — конфигурация базы обновляется. По умолчанию обновление **динамическое** (`-Dynamic+ -SessionTerminate force`): сеансы не прерываются; снятая галочка даёт нединамическое обновление, которому нужен монопольный доступ к базе.

Загрузка читает тот же каталог, что и выгрузка (`Каталог выгрузки` в параметрах проекта, по умолчанию корень проекта). Плагин **откажется** грузить каталог без `Configuration.xml`: такая загрузка заменила бы конфигурацию базы пустой. Перед запуском показывается подтверждение с перечислением последствий — замена конфигурации необратима, откат возможен только из вашего бэкапа (`.cf` / `.dt`).

### 🧩 Выгрузка расширений
Кнопка **«Выгрузить расширения»** выгружает **все** расширения базы в исходники: `DESIGNER /DumpConfigToFiles <каталог>\Extensions -Format Hierarchical -AllExtensions`. Отдельная подпапка `Extensions` рядом с конфигурацией обязательна: в общем каталоге объекты расширений смешались бы с объектами основной конфигурации.

Ключ `-AllExtensions` у `/DumpConfigToFiles` использует скрипт `db-dump-xml.ps1` из набора 1c-rules, и он же поддерживается `ibcmd` (`infobase config export all-extensions`); в справочнике по ключам Конфигуратора, доступном этому плагину, подтверждения не нашлось. Поэтому если версия платформы ключ не знает, выгрузка завершится ошибкой — плагин в этом случае прямо скажет, что дело в версии, а не в базе. Проверить вручную:

```powershell
& "C:\Program Files\1cv8\8.3.27.2130\bin\1cv8.exe" DESIGNER /F"C:\Bases\Buh" `
    /DumpConfigToFiles "C:\Projects\Buh\Extensions" -Format Hierarchical -AllExtensions `
    /DisableStartupDialogs /Out"C:\Temp\ext.log" /DumpResult"C:\Temp\ext.result"
```

Ориентир — файл `/DumpResult`: `0` означает успех.

### 📚 Подбор базы из списка 1С
Поле «Путь к базе» подсказывает базы из штатного списка 1С: читаются `%APPDATA%\1C\1CEStart\ibases.v8i` (список пользователя) и `%PROGRAMDATA%\1C\1CEStart\ibases.v8i` (общий список), а также внешние списки, подключённые параметром `CommonInfoBases` в `1cestart.cfg`. Файловые базы подставляются путём к папке, клиент-серверные — строкой `Srvr="…";Ref="…";`; базы через веб-сервер пропускаются (в пакетном режиме к ним не подключиться). Ввод вручную остаётся доступен.

### 🔌 Роуты `/1cprops/*` для других плагинов и агентов
Вся работа идёт через хост-роуты, ими же можно пользоваться снаружи: `GET /1cprops/project?path=…` отдаёт действующие параметры проекта с уже подставленным путём к платформе.

## Параметры

| Поле | Ключ в JSON | Значение |
|---|---|---|
| Путь к базе | `infobasePath` | папка файловой базы либо строка соединения `Srvr="srv";Ref="base";` |
| Пользователь | `user` | имя пользователя 1С |
| Пароль | `password` | пароль авторизации |
| Путь к платформе | `platformPath` | `…\bin\1cv8.exe`; пусто — берётся общее значение |
| Код доступа к базе | `unlockCode` | код для обхода блокировки установки соединений (`/UC`); пусто — не передаётся |
| Каталог выгрузки | `dumpDir` | куда писать XML; пусто — корень проекта |

Общие значения хранятся на машину: `$DSH_HOME/1c-project-properties/settings.json` (`$DSH_HOME` — переменная окружения, иначе `~/.dsh`).

## Файл параметров проекта

`<папка проекта>/.dsh/1c-project.json`, UTF-8, отступ 2:

```json
{
  "$schema": "dsh-1c-project-properties/v1",
  "infobasePath": "Srvr=\"srv-1c\";Ref=\"buh\";",
  "user": "Администратор",
  "password": "***",
  "platformPath": "",
  "unlockCode": "",
  "dumpDir": ""
}
```

- Запись атомарная (временный файл + переименование) — обрезанного JSON не будет.
- Плагин пишет только свои ключи; посторонние ключи в файле сохраняются.
- **Пароль лежит открытым текстом** — не коммитьте файл в git.

## Использование

1. Откройте **Settings → «1С: Параметры проектов»**.
2. В блоке **«Общие»** укажите путь к платформе по умолчанию — он подставляется во все проекты, где поле не заполнено.
3. Проекты: воркспейсы DSH попадают в список сами, папку без воркспейса добавьте полем под списком.
4. Нажмите на проект или на шестерёнку у строки — откроется окно **«Параметры проекта»**. Заполните путь к базе, пользователя и пароль, нажмите **«Сохранить»**: рядом с проектом появится `.dsh/1c-project.json`.
5. Путь к платформе в проекте задавайте, только если он отличается от общего. В том же окне: **«Удалить файл»** убирает параметры проекта, **«Убрать из списка»** — добавленный вручную путь.
6. Для выгрузки: проверьте **«Каталог выгрузки»** (пусто = корень проекта), выберите формат и нажмите **«Выгрузить конфигурацию в файлы»**. Идёт одна выгрузка за раз — Конфигуратор блокирует конфигурацию базы.
7. По завершении вкладка покажет число файлов, версию конфигурации и лог Конфигуратора. Если в базе остались lock-файлы `.cfl`, включите одноимённую галочку — иначе выгрузка завершится ошибкой блокировки.
8. Для обратной загрузки: **«Загрузить конфигурацию из файлов»** (галочки «обновить конфигурацию базы данных» и «динамическое обновление» — выше кнопки). Плагин покажет подтверждение с последствиями; каталог без `Configuration.xml` он грузить откажется.
9. **«Выгрузить расширения»** кладёт исходники всех расширений базы в подпапку `Extensions` того же каталога.
10. Для правил 1С: откройте окно проекта и нажмите **«Развернуть»** — набор [1c-rules](https://github.com/comol/ai_rules_1c) разложится в `.dsh/rules-1c`, `.dsh/agents-1c`, `.dsh/commands-1c`, `.dsh/skills` и `AGENTS.md` проекта. Повторное нажатие обновляет набор, не переписывая ваши правки; в раскрывающемся блоке — отчёт последнего запуска.

## Установка

Нужен `dsh` ≥ 0.1.2-rc.1. Ставится тремя способами — результат один и тот же.

**Из релиза** (скачивать ничего не нужно):

```sh
dsh plugin --profile web add https://github.com/Mempemp/DSH-1CProjectProperties/releases/download/v0.5.0/dsh-1c-project-properties-0.5.0.tgz
```

**Локальный архив** `dsh-1c-project-properties-0.5.0.tgz` (скачан со страницы релизов или собран самому: `cd dsh-1c-project-properties && npm pack`):

```sh
dsh plugin --profile web add dsh-1c-project-properties-0.5.0.tgz
```

**Папка плагина** (режим разработки, правки в `lib/*.js` подхватываются без переустановки):

```sh
dsh plugin --profile web add <путь к папке>/dsh-1c-project-properties
```

После установки перезапустите DSH (композиция плагинов читается на старте) и обновите страницу в браузере.

### Если `dsh` не в PATH

Локальная установка и DSH Desktop не добавляют `dsh` в `PATH` — вызывайте точку входа через node. Путь к `bin.js`:

| Как установлен DSH | Путь к `bin.js` |
|---|---|
| локально (`npm install @deepseek-ai/dsh`) | `<папка установки>\node_modules\@deepseek-ai\dsh\lib\bin.js` |
| DSH Desktop | `%LOCALAPPDATA%\Programs\DSH Desktop\resources\app\node_modules\@deepseek-ai\dsh\lib\bin.js` |

```powershell
node "C:\путь\к\dsh\lib\bin.js" plugin --profile web add "C:\путь\к\dsh-1c-project-properties-0.5.0.tgz"
```

### Возможные сложности

| Симптом | Что делать |
|---|---|
| `ERR_PNPM_UNEXPECTED_STORE` | добавить `--store-dir="<путь к вашему pnpm store>"` к команде установки |
| `EPERM` при записи в `…\profiles\web` | нет прав на папку профиля (песочница, антивирус): закрыть DSH, разрешить запись, повторить |
| Предупреждения про peer-зависимости (`cordis`, `react`, `react-dom`) | игнорировать: внешних зависимостей у плагина нет, react приходит из рантайма DSH |
| Путь к архиву содержит пробелы | ломается на `.cmd`-шиме pnpm — положите архив в путь без пробелов или поставьте папкой |
| После установки в `dsh.profile.bundles` появились лишние пакеты | `dsh plugin add` перезаписывает список слоёв: плагины, которые `dshmarket` держал «горячими» (`.dsh-market\hot-*.yml`), получают постоянную активацию. Ненужные строки можно удалить из `package.json` профиля, на работу плагина это не влияет |
| Вкладки нет после установки | DSH не перезапущен либо страница не перезагружена жёстко (`Ctrl+Shift+R`) |
| Выгрузка: «Ошибка блокировки информационной базы для конфигурирования» | в каталоге файловой базы остались lock-файлы `.cfl` — включите галочку **«снять .cfl перед выгрузкой»** (или закройте чужую сессию Конфигуратора) |
| Выгрузка: «Информационная база не обнаружена!» | неверный путь к базе: путь к папке с `1Cv8.1CD` либо строка `Srvr="…";Ref="…";` |
| Выгрузка мгновенно завершается «успешно», файлов 0 | указан `1cv8s.exe` (серверный агент) — в сессии пользователя он молча ничего не делает. Укажите `1cv8.exe` из того же `bin` |
| Выгрузка не стартует, если указан только каталог платформы | плагин сам ищет `1cv8.exe` в каталоге и в его `bin` — дайте либо файл, либо папку |
| В поле «Путь к базе» нет подсказок из списка | плагин читает `%APPDATA%\1C\1CEStart\ibases.v8i` и `%PROGRAMDATA%\1C\1CEStart\ibases.v8i`; если список ведётся в другом файле, подключите его в 1С через «Настройка → Списки общих баз» (попадёт в `CommonInfoBases` файла `1cestart.cfg`, плагин его тоже читает) |

Проверка, что хост-часть поднялась: `curl -s http://127.0.0.1:<порт>/1cprops/state` — должен вернуться JSON со списком проектов.

## Требования

- DeepSeek Harness (`dsh web` или DSH Desktop) ≥ 0.1.2-rc.1 — вкладка использует слот `settings.section`
- Node.js ≥ 20
- Платформа 1С:Предприятие 8.3 — только для кнопки выгрузки; путь задаётся в параметрах (`1cv8.exe` или каталог `bin`)
- Windows x64 — для платформенного контекста: сервер справки поставляется готовым `.exe`, внешние рантаймы (Java, Python) не нужны

## HTTP-роуты

| Метод и путь | Назначение |
|---|---|
| `GET /1cprops/state` | общие настройки, список проектов, найденные платформы 1С, базы из списка 1С (`infobases`), наличие набора правил (`rulesPayload`) |
| `POST /1cprops/common` | `{platformPath}` — сохранить общее значение |
| `GET /1cprops/platform-context` | состояние сервера справки: запущен ли, порт и адрес MCP, собран ли индекс платформы, отдан ли сервер MCP-менеджеру |
| `POST /1cprops/platform-context-restart` | перезапустить сервер справки (после смены версии платформы или по кнопке в настройках) |
| `POST /1cprops/project-save` | `{path, params}` — записать файл параметров проекта |
| `GET /1cprops/project?path=…` | действующие параметры проекта (общий путь к платформе подставлен) |
| `POST /1cprops/project-clear` | `{path}` — удалить файл параметров |
| `POST /1cprops/project-add` | `{path}` — добавить папку в список проектов |
| `POST /1cprops/project-forget` | `{path}` — убрать дополнительный путь из списка |
| `POST /1cprops/dump-start` | `{path, dir?, format?, update?, cleanLocks?}` — выгрузить конфигурацию в файлы (202, 409 если уже идёт операция) |
| `POST /1cprops/load-start` | `{path, dir?, format?, updateDb?, dynamic?, cleanLocks?}` — загрузить конфигурацию из файлов; `updateDb` (по умолчанию `true`) добавляет `/UpdateDBCfg`, `dynamic` (по умолчанию `true`) — `-Dynamic+ -SessionTerminate force` |
| `POST /1cprops/extensions-start` | `{path, dir?, extensionsDir?, cleanLocks?}` — выгрузить все расширения в `<dir>/Extensions` (по умолчанию корень проекта); `extensionsDir` переопределяет имя подпапки |
| `GET /1cprops/dump-status` | состояние текущей операции: `state`, `operation`, `label`, `counts`, время, файлы, версия конфигурации, лог Конфигуратора |
| `POST /1cprops/dump-cancel` | остановить операцию (убивает дерево процессов 1С) |
| `POST /1cprops/rules-deploy` | `{path, sections?, includePassword?, useEdt?, dryRun?, force?}` — развернуть/обновить правила в проекте; `dryRun: true` — предпросмотр |
| `POST /1cprops/rules-remove` | `{path, force?}` — убрать развёрнутые правила, вернув прежний `AGENTS.md` из бэкапа |

Набор правил хост-часть берёт из `$DSH_HOME/1c-rules` (его кладёт DSH Desktop при первом запуске) и складывает логи в `$DSH_HOME/1c-project-properties/jobs`.

## Структура репозитория

- `dsh-1c-project-properties/lib/index.js` — host-часть (ESM): роуты `/1cprops/*`, чтение и запись JSON, поиск установленных платформ 1С, запуск Конфигуратора в пакетном режиме.
- `dsh-1c-project-properties/lib/rules-deploy.js` — раскладка правил 1c-rules в проект: план и выполнение, переписывание ссылок, `.dev.env` из параметров проекта, манифест развёртывания `.dsh/1c-rules.json`, удаление.
- `dsh-1c-project-properties/lib/client.js` — клиентская часть: секция `settings.section` («1С: Параметры проектов»), список проектов и модальное окно параметров. Оформление — один инжектируемый `<style>` с классами `p1c-*` и переменными темы DSH (`--dsw-*`); инлайновых стилей в разметке нет.
- `dsh-1c-project-properties/lib/platform-context.js` — супервизор сервера справки: конфиг в `$DSH_HOME/1c-platform-context`, свободный порт, запуск `vendor/bsl-context-rs/bsl-context-rs.exe`, ожидание готовности индекса, остановка процесса, снимок состояния.
- `dsh-1c-project-properties/vendor/bsl-context-rs/` — сторонний бинарник сервера справки (v0.18.1, MIT) вместе с лицензией и происхождением (`VENDORED.md`). В репозитории лежит как есть, обновляется заменой файла.
- `dsh-1c-project-properties/cordis.patch.yml` — строка монтирования плагина в композицию профиля.
- `dsh-1c-project-properties/README.md` — описание пакета (то же, что и в архиве релиза).
- `dsh-1c-project-properties/test/rules-deploy.smoke.mjs` — проверка контракта развёртывания правил на синтетическом наборе: переписывание ссылок, чужой `AGENTS.md`, идемпотентность, сохранение правок, удаление. Запуск: `node test/rules-deploy.smoke.mjs` (внешних зависимостей нет).
- `dsh-1c-project-properties/test/platform-context.smoke.mjs` — проверка супервизора на настоящем бинарнике из `vendor/`: разбор путей к платформе (файл, каталог версии, каталог `bin`), запуск без пути, сборка индекса, `tools/list` по MCP, перезапуск, остановка. Запуск: `node test/platform-context.smoke.mjs`.
- `dsh-1c-project-properties/test/platform-context-host.smoke.mjs` — проверка хост-обвязки на поддельном `ctx`: регистрация сервера в MCP-менеджере, перезапуск после смены общего пути к платформе, снятие с учёта на выходе. Запуск: `node test/platform-context-host.smoke.mjs`.

Внешних зависимостей нет: только `node:*` и React из рантайма DSH.

## Безопасность

Пароль хранится в файле проекта открытым текстом — не коммитьте `.dsh/1c-project.json` в репозитории проектов. Хост-роуты доступны локально без токена сессии (как и роуты других плагинов через `ctx.webServer.register`); сервер DSH слушает `127.0.0.1`.

При развёртывании правил пароль базы в `.dev.env` **не** переносится, пока не включена соответствующая галочка: апстримные правила игнорируют `.dev.env` в git, но ваш проект может этого не делать. Плагин не правит `.gitignore` проекта и только предупреждает, что `.dev.env` стоит туда добавить.
