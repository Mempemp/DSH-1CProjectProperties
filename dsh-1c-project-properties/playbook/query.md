# Плейбук: запросы

Читать перед запросом сложнее одной выборки, при «медленно», при ревью запроса.
Базовые запреты — `code.md`, раздел «Запросы».

## Источник данных

- Справочные данные — справочник; бизнес-событие — документ; состояние на дату —
  срез периодического регистра сведений; количества и суммы — виртуальные таблицы
  регистра накопления. Не тот источник — дефект проектирования, а не повод
  «оптимизировать».
- Поля перечисляю явно, с псевдонимами. Лишнее поле — трафик из базы и лишнее
  определение типа.
- Результат — в переменную: `Результат = Запрос.Выполнить();`. Цепочку
  `Запрос.Выполнить().Выгрузить()` не пишу.

## Виртуальные таблицы

- Отбор по измерению — в параметры виртуальной таблицы, если результат тот же:

```bsl
// плохо: отбор после материализации
|ГДЕ Остатки.Склад = &Склад

// хорошо: отбор внутри виртуальной таблицы
|ИЗ РегистрНакопления.ТоварыНаСкладах.Остатки(&Момент, Склад = &Склад) КАК Остатки
```

- Условие виртуальной таблицы — **один** аргумент: запятая открывает следующий
  параметр, а не «И».
- Периодичность совпадает с полями соединения: соединение по `Регистратор` требует
  периодичности `Регистратор`, а не `Авто`.
- Отбор по реквизиту среза до среза и после — разные ответы. Сначала решаю, что нужно
  бизнесу, потом переношу отбор.

## Временные таблицы

- Каждая временная таблица, которая дальше идёт в `СОЕДИНЕНИЕ`, `ОБЪЕДИНИТЬ` или
  `В (ВЫБРАТЬ ...)`, создаётся с `ИНДЕКСИРОВАТЬ ПО` по полям соединения. Без индекса
  платформа сканирует её на каждую строку соединения — молча.
- Индексирую 2–3 самых селективных поля, не все. Таблица несёт ключи соединения и
  поля, которые реально нужны дальше.
- Один `МенеджерВременныхТаблиц` и один объект запроса на всю цепочку.
- Соединение с подзапросом не пишу: агрегат — во временную таблицу, потом соединение.
- Коррелированный подзапрос (`ГДЕ ИСТИНА В (ВЫБРАТЬ ПЕРВЫЕ 1 …)`) считается на каждую
  строку. Набор собираю один раз, индексирую, соединяю.

## Составные типы и представления

```bsl
// плохо: платформа раскрывает все типы регистраторов
|ТоварыНаСкладах.Регистратор.Дата КАК ДатаДокумента

// хорошо: тип назван явно
|ВЫРАЗИТЬ(ТоварыНаСкладах.Регистратор КАК Документ.ПоступлениеТоваровУслуг).Дата
```

- Несколько известных типов — `ВЫБОР … КОГДА … ССЫЛКА <Тип> ТОГДА ВЫРАЗИТЬ(…) …`.
- Нужен только текст — `ПРЕДСТАВЛЕНИЕ(Поле)`: лишнего соединения не будет.

## Объединения и отборы

- `ОБЪЕДИНИТЬ ВСЕ` по умолчанию. `ОБЪЕДИНИТЬ` — только когда дубли действительно
  нужно убрать: он делает лишнюю свёртку.
- `ИЛИ` в `ГДЕ` → `ОБЪЕДИНИТЬ ВСЕ` — кандидат на замер, не автоматическая правка.
  Ветки делаю непересекающимися: вторая с `И НЕ ЕСТЬNULL(<условие первой>, ЛОЖЬ)`.
- Перед замером сверяю, что набор строк не изменился: дубли, пересечение ветвей, `NULL`.

## Индексы

- Индекс работает, когда все поля условия есть в нём, стоят в начале и подряд.
  При индексе `(Организация, Контрагент, Дата)` условие `ГДЕ Контрагент = &К И Дата = &Д`
  индекс не использует.
- Часто фильтруемый реквизит — «Индексировать» в метаданных, по факту замеров, а не
  «на будущее».

## Проверка

- Переписал запрос — сначала сравниваю набор строк, потом время. «Стало быстрее» без
  замера не пишу; в ответе называю, что мерил: строки, число обращений к базе, время
  на реальном объёме.

## Если недоступно

- **`rlm` не отвечает.** Текст запроса читаю `read` по модулю, виртуальные таблицы
  проверяю по метаданным регистра (`get_object_full_structure` не нужен — хватает
  XML объекта), план запроса не снимаю и говорю об этом.
- **Нет доступа к базе для замера.** Переписываю по правилам выше, а в ответе пишу,
  что время не мерил: без замера «стало быстрее» — утверждение, а не факт.
