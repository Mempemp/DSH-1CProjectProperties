# Плейбук: метаданные

## Когда

- Новый реквизит, табличная часть, измерение, ресурс, реквизит адресации.
- Новое перечисление или значение существующего.
- Предопределённый элемент справочника или плана счетов, вид субконто.
- Новая роль, права, подписка на событие, регламентное задание, макет.
- Объект целиком (справочник, документ, обработка, отчёт, регистр).

Формы и элементы формы — `ui.md`. Код после правки — `edit.md`.

## Чем

- Навык набора — первым. Навыки лежат в `.dsh/skills`: ищу подходящий
  `glob` по `.dsh/skills/**/SKILL.md`, загружаю `skill`. Имя навыка не выдумываю:
  беру из списка найденных файлов.
- Чтение состава до правки: `get_object_full_structure(name)`,
  `find_attributes(object_name=...)`, `find_predefined(object_name=...)`,
  `find_templates(owner=...)` — через `rlm_start`/`rlm_execute` (`find.md`).
- Сам XML: `read`, `grep`, `glob`, `edit`, `write`. `edit` — точечно, `write` —
  только новый файл.
- `validate_module` — после правки модулей объекта и менеджера.
- `v8std_search` — требования к объекту: обязательные реквизиты, именование,
  поведение при проведении.

## Порядок

1. Читаю состав объекта целиком: `get_object_full_structure`. Правлю по факту,
   а не по предположению о структуре выгрузки.
2. Проверяю, нет ли уже такого элемента: `find_attributes(object_name=...)`,
   `grep` по файлу объекта. Дубль имени в одной коллекции — ошибка.
3. Ищу навык под этот вид объекта (`.dsh/skills`). Навык есть — работаю им,
   включая генерацию идентификаторов и правку `Configuration.xml`.
4. Навыка нет — правлю XML по образцу соседнего объекта того же вида: те же узлы,
   тот же порядок, те же отступы. Новому элементу — собственный `uuid`
   (`pwsh`: `[guid]::NewGuid()`), чужой идентификатор не копирую.
5. Новый объект добавляю в `Configuration.xml` в `ChildObjects` — без этого
   платформа его не увидит.
6. Проверяю: `grep` на дубли имён и идентификаторов, затем `validate_module` по
   модулям объекта и менеджера.
7. Называю человеку, что изменение вступит в силу после загрузки конфигурации в
   базу и обновления конфигурации БД (`db.md`); сам базу не трогаю.

## Проектирование регистров

- Вид регистра — по смыслу: справочные данные — справочник, событие — документ,
  количества и суммы с оборотами — регистр накопления, произвольные данные с
  измерениями и периодичностью — регистр сведений, проводки и субконто — регистр
  бухгалтерии.
- Измерение — то, по чему режут отчёты и нужны остатки. Признак, который только
  показывают, — реквизит. Ресурс — то, что суммируется; остальное реквизит.
- Периодичность ставлю осознанно: `СрезПоследних`/`СрезПервых` есть только у
  периодического регистра сведений.
- Остатки нужны, только если бизнес спрашивает «сколько есть». Только «сколько прошло
  за период» — регистр без остатков.
- Индекс — под фактические отборы и соединения, «индексировать всё» удорожает запись.
- Перепроведение: новые движения пишутся в `ОбработкаПроведения`, старые снимаются
  `Очистить()` до записи набора. Иначе после перепроведения остаются хвосты.

## Имя и вид объекта

- Новый объект, реквизит, роль, элемент на типовой форме — с префиксом
  расширения/проекта. Внутри своего объекта префикс не повторяю.
- Синоним — без префикса; конфликт синонимов — уточнение в скобках.
- Справочные данные — справочник; операция — документ; накопление — регистр
  накопления; произвольные данные с измерениями — регистр сведений; отчёт для
  пользователя — отчёт на СКД; разовая обработка — обработка; фиксированный набор —
  перечисление.
- Составной тип, повторяющийся в нескольких местах, — `ОпределяемыйТип`, а не строка
  типов в каждом реквизите.
- Новый объект попадает в подсистему — иначе его не найдут в интерфейсе.

## Если недоступно

- **Навыка под этот вид объекта нет.** Правлю XML руками по образцу соседнего
  объекта и пишу в ответе, что правка ручная и какой объект взят за образец.
- **`rlm` недоступен.** Состав читаю `read` по файлам объекта (`<Объект>.xml`,
  каталог `Ext`, `Forms`, `Templates`), поиск — `grep`.
- **Правка ломает загрузку** (платформа отвергает XML при загрузке). Откатываю
  файл по git или вручную, затем повторяю по шагам; «доправливать на глаз» в
  сломанном XML нельзя.
- **Метаданные в расширении.** Сначала `glob` по каталогу расширения и проверка,
  что объект не заимствован: заимствованный объект правится в расширении только
  по своим свойствам, состав — в основной конфигурации.
- **Нужен стандарт по объекту, а `v8std` молчит.** Не выдумываю требования:
  делаю по образцу работающего объекта проекта и помечаю это в ответе.
