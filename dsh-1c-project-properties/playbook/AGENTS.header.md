# 1С в этом проекте

Исходники конфигурации 1С: выгрузка в XML-файлы или каталог EDT. Истина о коде и
метаданных — в файлах проекта; платформа, база и данные — снаружи, за параметрами
проекта. Отвечаю человеку по-русски, имена в коде — как в конфигурации.

## Что установлено

| Группа | Что это | Чем зову |
|---|---|---|
| Код 1С | MCP `rlm`: индекс по выгрузке (модули, объекты, вызовы, макеты) | `rlm_start` → `rlm_execute`; хелперы `find_module`, `find_by_type`, `get_object_full_structure`, `safe_grep`, `git_search` |
| Платформа | MCP `1c-platform-context`: справка платформы и валидатор BSL | `search`, `info`, `get_members`, `get_constructors`, `validate_module` |
| Стандарты | MCP `v8std`: знания по платформе и БСП | `v8std_search`, `v8std_get_page`, `v8std_get_related`, `v8std_explain_snippet`, `v8std_explain_diagnostics` |
| Стандарты ИТС | MCP `1c-naparnik`: ответы по ИТС, БСП и методичкам словами | `its_help` |

Какие серверы реально настроены в этом проекте — `.dsh/rules-own/environment.md`.

Плейбук читается до работы, а не после. Задача не попадает ни в одну строку
таблицы — работаю по этому файлу и `platform.md`.

## Жёсткие правила

1. **API платформы проверяю до кода.** Метод, свойство, конструктор, значение
   перечисления, число аргументов — сначала `platform.md`, потом текст модуля.
   Память и аналогия с соседними версиями платформы доказательством не считаются.
2. **После правки модуля — `validate_module`** (сервер `1c-platform-context`).
   Правка без проверки не считается сделанной: находки `high` устраняются, `low`
   проверяются и объясняются. `symbols_available: false` называю человеку прямо.
3. **Метаданные руками не правлю, если есть навык.** Сначала навык под вид
   объекта (`glob` по `.dsh/skills/**/SKILL.md`, затем `skill`); ручная правка
   XML — только когда навыка нет, по образцу соседнего объекта того же вида и с
   предупреждением в ответе.
4. **Значения не выдумываю.** База, пользователь, версия платформы, каталог
   выгрузки — в `.dsh/1c-project.json`. Пусто — спрашиваю человека, а не
   подставляю правдоподобное.
5. **Инструментов вне таблицы не изобретаю.** Никаких `syntaxcheck`,
   `trace_impact` и подобных: инструмент не отвечает — ухожу в ветку «Если
   недоступно» своего плейбука и говорю об этом. Молчаливое «сделаю как
   получится» запрещено.
6. **`its_help` — наводка, не доказательство.** Имена и типы проверяю по
   `platform.md`, существование объектов — по `rlm` (`safe_grep`,
   `get_object_full_structure`). Ответ без сверки в код не идёт.
7. **Секреты не печатаю.** Пароль базы, токен Напарника, содержимое `.dev.env` не
   попадают в ответ, лог, коммит и текст ошибки.

## Порядок при конфликте

Правила владельца (`USER-RULES.md`) выше этого файла, этот файл выше плейбука;
стиль окружающего кода выше шаблона — кроме данных, блокировок и безопасности,
там шаблон строже.

## Готово — значит проверено

Работа закончена, когда проверка прогнана и я назвал, чем именно проверял. Что
проверить не смог — говорю прямо, а не выдаю за сделанное.

## Ещё в проекте
