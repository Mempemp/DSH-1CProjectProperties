# Плейбук: формы и интерфейс

## Когда

- Нужно добавить, переставить или скрыть элемент формы.
- Нужен новый реквизит формы, команда формы, условное оформление.
- Правлю модуль формы: обработчики `ПриСозданииНаСервере`, `ПриОткрытии`,
  `ПриИзменении`, клиентские процедуры.
- Меняю командный интерфейс: разделы, команды, видимость по ролям.
- Нужно понять, какие формы есть у объекта и какая из них основная.

Состав объекта (реквизиты, ТЧ) — `metadata.md`. Элемент формы показывает данные,
которых в объекте нет, только если это реквизит самой формы.

## Чем

- `get_object_full_structure(name)` — список форм объекта (`forms`) через
  `rlm_start`/`rlm_execute` (`find.md`).
- `find_module(name, module_type='FormModule')` — файл модуля формы.
- `glob` — найти `Form.xml` и `Ext/Form/Module.bsl` в каталоге формы; `read`,
  `grep` — прочитать форму и её модуль.
- Навык набора — первым: `glob` по `.dsh/skills/**/SKILL.md`, затем `skill`.
  Навык знает раскладку `Form.xml`, порядок узлов и генерацию идентификаторов.
- `edit`, `write` — правка XML и модуля формы.
- `validate_module(path=..., module_path=...)` — проверка: с `path` сервер читает
  `Form.xml` рядом с модулем и ловит `Элементы.<Имя>`, которых в форме нет.
- `reserved_names()` — имя переменной или процедуры не занято контекстом формы.
- `v8std_search`, `v8std_get_page` — требования к управляемым формам, поведение
  элементов, стандарты интерфейса.

## Порядок

1. Нахожу форму: `get_object_full_structure` → `forms`, затем `glob` по
   `<Объект>/Forms/<Форма>/`. Правлю ту форму, которую назвал человек; основную
   выбираю по `DefaultForm`/`DefaultObjectForm` в XML объекта.
2. Читаю `Form.xml` и `Ext/Form/Module.bsl` до правки. Решение об элементе
   принимаю по фактическому составу формы, а не по памяти о типовой конфигурации.
3. Ищу навык под формы. Есть — работаю им: он держит раскладку XML и
   идентификаторы. Нет — правлю XML по образцу соседнего элемента той же формы.
4. Элемент привязываю к существующему реквизиту: имя в `DataPath` сверяю с
   `Form.xml` (`Attributes`) или с объектом (`find_attributes`). Опечатка в пути
   данных — форма не откроется.
5. Модуль формы правлю `edit`; вызовы платформенных методов сверяю по
   `platform.md` до текста.
6. `validate_module(path=...)` по файлу модуля формы. Находки
   `unknown_form_element` — это элементы, которых в `Form.xml` нет: исправляю имя
   или добавляю элемент.
6a. Проверяю связку: каждый обработчик привязан в `Form.xml` (`Events`) и имеет
    директиву своего события; каждый `Action` команды есть в модуле ровно один раз.
7. Смотрю `reserved_names()`: имя, занятое контекстом формы, не использую.
8. Говорю человеку, что форму нужно открыть в базе после загрузки конфигурации и
   обновления конфигурации БД (`db.md`).

## Если недоступно

- **Навыка под формы нет.** Правлю `Form.xml` руками по образцу соседнего
  элемента, пишу в ответе, что правка ручная. Новому элементу — собственный
  `uuid` (`pwsh`: `[guid]::NewGuid()`), чужой не копирую.
- **`validate_module` вызван без `path`.** Проверка элементов формы не работает:
  `Элементы.<Имя>` в таком режиме не сверяются. Передаю `path` файла модуля
  внутри корня выгрузки; файл вне корня — говорю, что состав формы не проверен.
- **`Form.xml` большой.** Читаю `read` частями по нужным узлам (`Elements`,
  `Attributes`, `Commands`), а не файл целиком в контекст.
- **`rlm` недоступен.** Формы ищу `glob` по `<Объект>/Forms/*/Form.xml`, основную —
  `grep` по `DefaultForm` в XML объекта.
- **`v8std` молчит.** Требования к форме не выдумываю: делаю по образцу
  работающей формы проекта и помечаю это в ответе.
