# Плейбук: платформа и стандарты

## Когда

- Пишу вызов платформенного метода, свойства, конструктора — до текста модуля.
- Нужно значение системного перечисления (`ВидДвиженияНоменклатуры.Приход`).
- Надо проверить число аргументов глобальной функции.
- Надо проверить имя процедуры или переменной на занятость контекстом.
- Нужен стандарт разработки, требование БСП, пример правильного кода.
- Надо разобрать код находки анализатора (`acc 1245`, `bslls:...`).

Проверка целого модуля после правки — `edit.md`; правка метаданных — `metadata.md`.

## Чем

MCP `1c-platform-context` (справка платформы версии из `platformPath` и
валидатор BSL):

| Инструмент | Аргументы | Назначение |
|---|---|---|
| `search` | `query, limit` | нечёткий поиск типа, метода, свойства по имени |
| `info` | `name, kind` | точное имя: `kind` — `type`, `method`, `property` |
| `get_members` | `type_name` | все члены типа: методы, свойства, значения перечисления |
| `get_member` | `type_name, member_name` | один член типа |
| `get_constructors` | `type_name` | конструкторы с сигнатурами |
| `get_enum_values` | `type_name` | значения системного перечисления |
| `validate_enum` | `type_name, value_name` | существует ли значение |
| `validate_method_call` | `method_name, arg_count` | попадает ли число аргументов в перегрузки |
| `reserved_names` | — | имена, занятые глобальным контекстом и контекстом формы |
| `validate_module` | `source` или `path`, `module_path`, `level`, `profile`, `repo` | проверка модуля или фрагмента |

MCP `v8std` (публичный сервер знаний, работает без ключа):

| Инструмент | Аргументы | Назначение |
|---|---|---|
| `v8std_search` | `query, limit, types, mode, cursor` | найти статью по вопросу словами; отдаёт id, заголовки, ссылки |
| `v8std_get_page` | `id_or_alias_or_url, body_limit` | прочитать статью по id (`stdNNN`) или ссылке |
| `v8std_get_related` | `id_or_alias_or_url, relations, limit` | связанные стандарты и диагностики |
| `v8std_explain_snippet` | `snippet, language, limit` | фрагмент BSL/SDBL против сигналов базы знаний |
| `v8std_explain_diagnostics` | `codes` | разобрать коды диагностик до 500 штук |

## Порядок

1. Имя платформенного элемента помню неточно — `search(query="...")`, затем
   `info(name="...")` по точному имени.
2. Метод или свойство типа: `get_members(type_name)` для обзора,
   `get_member(type_name, member_name)` для деталей; сигнатуру беру оттуда, а не
   из памяти.
3. Конструктор: `get_constructors(type_name)` — только существующие перегрузки.
4. Перечисление: `get_enum_values(type_name)` до написания значения,
   `validate_enum(type_name, value_name)` — сомнительное значение.
5. Число аргументов: `validate_method_call(method_name, arg_count)`.
6. Имя своей процедуры или переменной: `reserved_names()` — совпало с занятым,
   переименовываю.
7. Стандарт или «как принято»: `v8std_search` по вопросу → `v8std_get_page` по
   id. Ссылку на статью кладу в ответ человеку.
8. Разбор находки анализатора: `v8std_explain_diagnostics(codes=[...])`, затем
   `v8std_get_related` за стандартом.

## Если недоступно

- **`1c-platform-context` не отвечает.** `symbol_sources_status()` — состояние
  источников; `reconnect_symbol_source(repo=...)` — повторить подключение;
  `reload_config()` — перечитать конфиг, если его правили руками (применяется
  только список источников); `rebuild_symbol_index(repo=...)` — пересобрать
  индекс имён. `repo` передаю, только если источников несколько.
- **Сервер не поднят вовсе** (не задан путь к платформе). Панель «Платформенный
  контекст (MCP)» в настройках плагина показывает причину; путь задаёт человек.
  Пока сервера нет, справку беру из `v8std` и помечаю в ответе, что по платформе
  не проверено.
- **`validate_module` вернул `symbols_available: false`.** Проверены только
  платформенные правила, находки `undeclared_method` понижены — модуль не
  считать чистым, причину (`degraded_reason`) назвать человеку.
- **`v8std` недоступен (нет сети).** Остаются `search`/`info` платформенного
  сервера и `web_search`/`read_page`; стандарт, прочитанный не из `v8std`,
  помечаю как внешний источник, а не как стандарт ИТС.
- **Оба сервера молчат.** Код не пишу «по памяти»: говорю, что проверка API
  невозможна, и предлагаю поднять сервер.
