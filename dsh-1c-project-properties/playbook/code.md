# Плейбук: код 1С

Когда читать: перед новой процедурой или модулем, перед правкой чужого `.bsl`,
при ревью, при выборе между запросом, регистром и расширением.

Порядок работы:

1. Найти, как это уже сделано в конфигурации: `find_module`, `safe_grep`,
   `get_object_full_structure`. Своё решение — только если готового нет.
2. Проверить метод и типы по своей версии платформы: `search`, `get_member`,
   `get_constructors`. Сигнатуры не выдумывать.
3. Писать по правилам ниже.
4. После правки — `validate_module` по `path`, разобрать находки.
5. Спорное правило — `v8std_search` с `types: ["standard"]`, затем
   `v8std_get_page`. Номера стандартов ниже проверены по корпусу.

## Структура модуля

Стандарт: структура модуля.

- Общий модуль: `ПрограммныйИнтерфейс` → `СлужебныйПрограммныйИнтерфейс` →
  `СлужебныеПроцедурыИФункции`. При необходимости `ИнициализацияМодуля` в конце.
- Модуль объекта и менеджера: внешний блок
  `#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда`
  … `#КонецЕсли`. В стандарте этого блока нет — это наше ужесточение, чтобы код не
  компилировался в тонком клиенте.
- Модуль формы: `ОбработчикиСобытийФормы` → `ОбработчикиСобытийЭлементовШапкиФормы`
  → `ОбработчикиСобытийЭлементовТаблицФормы` → `ОбработчикиКомандФормы` →
  `СлужебныеПроцедурыИФункции`.
- Области внутри процедур, псевдо-области комментариями (`// ---`) и код вне
  областей запрещены. Один метод — одна область.

## Имена

Стандарты: имена переменных, имена процедур и функций, параметры процедур и функций.

- Имя от терминов предметной области, а не от типа. Без венгерской нотации:
  `Контрагенты`, не `МассивКонтрагентов`; исключение — коллекции:
  `ТаблицаКлиентов`, `СписокДокументов`.
- Не занимать имена глобального контекста: `Документы`, `Справочники`,
  `РегистрыСведений`, `Метаданные`, `Константы`, `ПараметрыСеанса`.
- Процедуры — действие (`ЗаполнитьТаблицу`), функции-предикаты — `ЭтоНовый`,
  `ЕстьОшибки`, функции-получения — `ПолучитьДанные`, `НайтиКлиента`.
- Сокращения только общепринятые; `ИБ`, `ТЧ`, `СКД`, `БСП` — можно.

## Документация и комментарии

Стандарт: описание процедур и функций.

- У каждой процедуры и функции — шапка: что делает по существу, чего не делает,
  `Параметры:` (имя — тип — назначение) и `Возвращаемое значение:` у функций.
- В теле — только причина неочевидного решения, ограничение, граничный случай,
  `TODO` с номером задачи. Пересказ кода (`// Получаем данные`) запрещён.
- Шапка описывает контракт, а не факт существования метода.

## Запросы

Стандарты: запросы в цикле, обращения к виртуальным таблицам,
оформление текста запроса.

- Запрос внутри цикла запрещён. Собирать ключи и выполнять один запрос на набор;
  запись — пачкой, не по одной записи в цикле.
- Параметры — через `УстановитьПараметр`, не склейкой строк. Никакой конкатенации
  значений в текст запроса.
- Поля перечислять явно, с псевдонимами; `*` — нет.
- Соединение с виртуальной таблицей: сначала `ПОМЕСТИТЬ` с отбором и параметрами,
  затем соединение с временной таблицей. `ИНДЕКСИРОВАТЬ ПО` — 2–3 самых
  селективных поля соединения, не все.
- Условие виртуальной таблицы — **один** аргумент:
  `Остатки(&Момент, Склад = &Склад И Номенклатура = &Номенклатура)`.
  Запятая открывает следующий параметр, а не «И» — это ошибка.
- `СрезПоследних` и `СрезПервых` существуют только у периодических регистров
  сведений.
- Имена ресурсных полей виртуальной таблицы производные:
  `КоличествоОстаток`, `СуммаОборот`, `КоличествоНачальныйОстаток`. Брать из
  метаданных, суффикс не угадывать.
- `РАЗЛИЧНЫЕ` не добавлять поверх `СГРУППИРОВАТЬ ПО` и внутри `ОБЪЕДИНИТЬ`.
- `ПЕРВЫЕ N` — только вместе с `УПОРЯДОЧИТЬ`.
- Внешнее соединение: `ЕСТЬNULL` там, где ожидается число или строка.
- Коррелированный подзапрос в соединении — заменить индексированной временной
  таблицей.
- Составной тип называют явно: `ВЫРАЗИТЬ(Регистратор КАК Документ.ПоступлениеТоваровУслуг).Дата`.
  Без `ВЫРАЗИТЬ` платформа раскрывает все типы и соединяет по каждому. Нужен только
  текст — `ПРЕДСТАВЛЕНИЕ(Поле)`, лишнего соединения не будет.
- `ОБЪЕДИНИТЬ ВСЕ` по умолчанию; `ОБЪЕДИНИТЬ` — только когда дубли действительно
  нужно убрать.
- Временная таблица, которая дальше идёт в соединение, — всегда с `ИНДЕКСИРОВАТЬ ПО`
  по полям соединения. Без индекса платформа сканирует её на каждую строку.
- Подробности — `query.md`.

## Клиент-сервер

Стандарты: минимизация серверных вызовов, директивы компиляции.

- Один серверный вызов на операцию, данные передавать пачкой. Несколько
  `&НаСервере` подряд ради одной операции — дефект.
- `&НаСервереБезКонтекста` там, где контекст формы не нужен.
- Не передавать объекты и большие коллекции на клиент без необходимости.
- Директивы — по назначению, не «на всякий случай». Обработчик формы без директивы
  не компилируется.

## Транзакции и блокировки

Стандарты: правила использования транзакций, управляемый режим блокировки,
блокировка объекта для редактирования.

- Режим блокировки — управляемый. В новой конфигурации автоматический не включаю,
  в старой не расширяю.
- Транзакция — на операцию, а не на метод: чтение остатков, проверки и запись
  движений идут внутри одной.
- `Записать()`, `Провести()`, `ЗаписатьНабор()` открывают неявную транзакцию. Запись
  в цикле — это N транзакций и N захватов: пишу пачкой в одной.
- В `ПриЗаписиНаСервере`, `ПередЗаписьюНаСервере` транзакция уже открыта платформой.
  `НачатьТранзакцию()` внутри — вложенная транзакция с непредсказуемым откатом.
- Порядок захвата одинаков во всех процедурах: сначала регистры, потом справочники,
  внутри — по имени. Разный порядок в двух местах — это дедлок.
- `НачатьТранзакцию()` — до `Попытка`; `ЗафиксироватьТранзакцию()` и
  `ОтменитьТранзакцию()` — внутри; парность на всех ветках.
- `Заблокировать()` — только внутри `Попытка`, снятие автоматическое. Блокирую
  минимальный набор: конкретные измерения и элементы, не всю таблицу.
- Внутри транзакции — ни диалога, ни HTTP, ни файловых операций, ни `Ждать`, ни
  длительных вычислений.
- Разбор ошибки — `ПодробноеПредставлениеОшибки()`, а не `ОписаниеОшибки()` в лог.

## Асинхронность (8.3.18+)

- `Асинх` на методе и `Ждать` на вызове — парой. Вызов без `Ждать` возвращает
  `Обещание`, а исключение внутри теряется молча: ни сообщения, ни стека.
- Результат `Ждать` — значение метода или `Неопределено`, если внутри было
  исключение. После `Ждать` проверяю, что получил.
- Обработчик формы с `Асинх` форму не блокирует: код после `Ждать` выполняется позже,
  форма может быть уже закрыта — проверяю, что она открыта.
- `ОписаниеОповещения` — только там, где платформа ещё не даёт `Асинх` (старый режим
  совместимости). Два стиля в одной процедуре не смешиваю.

## Исключения

Стандарты: перехват и вызов исключений.

- `Попытка` — там, где ошибку можно обработать, а не вокруг каждого вызова.
- Пустой блок `Исключение` запрещён. Минимум — запись в журнал с контекстом
  (объект, операция, параметры).
- Не превращать ошибку в «успех»: частичный результат не выдавать за полный.
- Сообщение пользователю — `ОбщегоНазначения.СообщитьПользователю`, не `Сообщить`.
- Не глотать исключение, чтобы «не падало»; если решение осознанное — сказать об
  этом в ответе.

## Обращение к реквизитам через точку

Стандарт: чтение отдельных реквизитов объекта; наше правило строже.

- `Ссылка.Реквизит` в цикле и в массовых операциях запрещено: это отдельный
  запрос на каждую ссылку. Читать одним запросом или через
  `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` (и пакетные варианты).
- Одиночное чтение вне цикла стандарт допускает; у нас — только если иначе
  не получается, и это видно в коде.

## Выполнить и Вычислить

Стандарты: ограничения на использование Выполнить и Вычислить на сервере и на клиенте.

- На сервере — только с `УстановитьБезопасныйРежим`.
- На клиенте — не использовать.
- Если задачу можно решить без них — решать без них.

## Журнал регистрации

- `ЗаписьЖурналаРегистрации` — когда это нужно по задаче (разбор обмена, аудит
  действий, диагностика инцидента), не «на всякий случай».
- Уровень: `Информация` — ход процесса, `Предупреждение` — обошли проблему,
  `Ошибка` — операция не выполнена. Успех пишу `Информацией`.
- Категория — устойчивое имя подсистемы (`Обмен.Заказы`), не имя процедуры и не
  текст задачи. В комментарии — объект, операция, ключ, без пересказа кода.
- Пароли, токены, персональные данные и полные тексты документов в журнал не пишу:
  идентификатор, а не содержимое.
- Журнал не заменяет сообщение пользователю: пользователю —
  `ОбщегоНазначения.СообщитьПользователю`.

## Запрещённые конструкции

- Тернарный оператор `?(...)` — нет.
- Сравнение с `Истина`/`Ложь` (`= Истина`) — нет: `Если Флаг Тогда`, `Если Не Флаг Тогда`.
- Магические числа и строки — в константу, реквизит или именованную переменную.
- Отрицательные булевы (`НеАктивен`) — нет: `Активен`.
- «ё» в идентификаторах (объекты, реквизиты, процедуры, алиасы) — нет.
- `Попытка` вокруг чтения или записи объекта — нет: ошибку базы обрабатывает
  платформа. `Попытка` — вокруг того, что я действительно могу обработать.
- Сборка длинной строки через `+` в цикле — `Массив` и `СтрСоединить`.
- Вложенность глубже трёх уровней и метод длиннее экрана — сигнал разделить; порог
  не догма, отклонение объясняю.

## Правка типового кода

Проект — доработка типовой. Правки в типовых модулях помечаю, иначе обновление
непроверяемо:

```bsl
// +++ Иванов, 2026-11-06, задача 14752
НовоеЗначение = ПреобразоватьЗначение(Значение1);
// ТиповаяПроцедура(Значение1, Значение2);
ТиповаяПроцедура(НовоеЗначение, Значение2);
// ---
```

- Маркеры — парой, с автором, датой и номером задачи; пространство после `//`
  обязательно.
- Удалённую типовую строку не удаляю, а комментирую: при обновлении видно, что было.
- В модуле своего объекта (имя с префиксом) маркеры не нужны: один блок в шапке
  модуля — что это за объект.
- `TODO`/`FIXME` — только с номером задачи.

## Формы

Стандарты: проверка заполнения, программное управление формой.

- Локальные переменные модуля формы нельзя называть `ПараметрыВыбора`,
  `СвязиПараметровВыбора`, `СписокВыбора`, `ПараметрыОтбора`, `ОтборСтрок`:
  на `&НаСервере` платформа трактует присваивание как установку свойства элемента
  формы и падает с «Несоответствие типов».
- `РеквизитФормыВЗначение` и `ЗначениеВРеквизитФормы` — только из `&НаСервере`.
- Не передавать объект (`СправочникОбъект`, набор записей, результат
  `РеквизитФормыВЗначение`) в `ЗначениеЗаполнено`: компилируется, но падает в
  рантайме.
- Не добавлять реквизит формы с именем поля объекта — значение останется в форме
  и не дойдёт до объекта.
- Не дублировать на форме объекта команды «Записать», «Провести», «Провести и
  закрыть»: их даёт `AutoCommandBar`. `ОбработкаПроведения` и `ПередПроведением` —
  события модуля объекта, а не формы.
- Форма записи регистра сохраняет стандартные команды, только пока основная
  таблица — `Запись` типа `InformationRegisterRecordManager.<Имя>`
  с `SavedData = true`.
- В модуле формы обязательны пять областей: `ОбработчикиСобытийФормы`,
  `ОбработчикиСобытийЭлементовШапкиФормы`,
  `ОбработчикиСобытийЭлементовТаблицыФормы<Имя>` (своя на каждую табличную часть),
  `ОбработчикиКомандФормы`, `СлужебныеПроцедурыИФункции`. Пустую область оставляю.
- Обработчик в модуле не работает, пока событие не привязано в `Form.xml`
  (`<Events><Event name="OnOpen">ПриОткрытии</Event></Events>`). Имя в XML без метода —
  форма не открывается; директива — по событию.
- `ПослеЗаписи` на клиенте и `ПриЗаписи` в модуле объекта — разные события.
- Перед записью — `Если Не ПроверитьЗаполнение() Тогда Возврат; КонецЕсли;` и
  свойство «Проверка заполнения» у реквизитов. Ручные проверки «если пусто —
  сообщить» дублируют платформу и расходятся с ней.

## Метаданные XML

- В табличных частях не писать блок `<standardAttributes>` с `LineNumber`:
  платформа добавляет его сама, загрузка падает.
- Тип `PagesGroupExtInfo` — с буквой «s»; иначе группа страниц молча не грузится.
- Каждая `<Page>` требует `<enabled>true</enabled>`.
- UUID только генерировать. Copy-paste и последовательные заглушки запрещены:
  дубли UUID ломают загрузку.
- Замок вендорской поддержки (`Ext/ParentConfigurations.bin` рядом с
  `Configuration.xml`) правкой XML не обходится: только расширение или
  осознанный `support-edit`.

## Расширения

- `&ИзменениеИКонтроль` предпочтительнее `&Вместо` (доступно с 8.3.18).
- В `&Вместо` обязателен `ПродолжитьВызов`, если это не полная замена; полная
  замена заявляется в шапке метода.
- Маркеры `#Вставка` и `#Удаление` — с колонки 0; неизменённые строки — дословно;
  замена — удаление плюс вставка.
- Новые объекты и методы расширения — с префиксом расширения. Алиас расширения
  (`Расш1_`) — не то же самое, что префикс; «ё» в алиасе не использовать.
- `ПродолжитьВызов` — только в `&Вместо`, `&Перед`, `&После`. В `&ИзменениеИКонтроль`
  его нет: тело оригинала уже скопировано, вызов даст второй проход.
- `&ИзменениеИКонтроль`: неизменённые строки — дословно из оригинала. Правка
  неотмеченной строки ломает контроль, и после обновления типовой расширение молча
  перестаёт применяться. После обновления вендора неизменённый контекст сверяю.
- `&После` без такого метода в оригинале молча не срабатывает: имя проверяю в
  оригинальном модуле, а не по памяти.
- Заимствованный объект: состав (реквизиты, ТЧ) правится в основной конфигурации, в
  расширении — свойства и обработчики. Новый реквизит заимствованного объекта — с
  префиксом.

## Где смотреть детали

Стандарты не переписаны в плейбук: их отдаёт внешний сервис `v8std`.
`v8std_search(query, types: ["standard"])` → `v8std_get_page(id)`.
Номер стандарта — это ответ сервиса на момент запроса, а не наш контракт:
не запоминать его, не хардкодить и не рассчитывать, что он не изменится.
Если сервиса нет в сборке или он недоступен — работаю по правилам этого файла
и справке платформы, а в ответе пишу «стандарт не проверял».

## Чем проверять

- `validate_module` с `path` — синтаксис, вызовы, часть семантики. Возвращает
  находки со строками, модуль в контекст не тащит.
- `v8std_explain_snippet` — спорный фрагмент; `v8std_explain_diagnostics` —
  объяснение диагностики.
- Пустой список находок не доказывает, что код хорош: стиль, имена и структуру
  `validate_module` не проверяет. Об этом говорить прямо.
- `v8std` недоступен — сказать «стандарт не проверял», опереться на справку
  платформы и код вокруг. Номер стандарта не выдумывать.

## Конфликт с окружающим кодом

- Отступы, регистр ключевых слов, язык комментариев — как в модуле.
- Имена, целостность данных, блокировки, безопасность, обработка ошибок — не
  уступают стилю. Отклонение от стандарта называть явно.

## Чек-лист перед сдачей

- Имена и шапки методов соответствуют правилам.
- Нет запроса в цикле и чтения реквизита через точку в цикле.
- Транзакция и блокировки парные, короткие, без диалога внутри; порядок захвата
  тот же, что в соседних процедурах.
- Временные таблицы, участвующие в соединении, проиндексированы по полям соединения.
- Обработчики форм привязаны в `Form.xml`, директивы совпадают с событиями.
- Блоки `Исключение` не пустые, ошибка не выдана за успех.
- Клиент-серверных вызовов не больше, чем нужно для операции.
- `validate_module` без новых ошибок; предупреждения разобраны или объяснены.
- Спорные места сверены с `v8std` или помечены как непроверенные.

## Частые ошибки

- API, которого нет в режиме совместимости проекта: код не соберётся или поведёт
  себя иначе. Сверять по версии платформы, а не по последней справке.
- Выдуманная сигнатура метода БСП: параметры, порядок, возвращаемое значение.
  Читать реальный модуль своей версии.
- Путаница клиента и сервера: `&НаКлиенте` с серверным вызовом, объект на клиенте.
- Вывод «функционала нет» по одному слою: конфигурация и расширения проверяются
  обе.
- Правка метаданных текстом вместо инструмента: ломает XML и связи.
- «Тесты прошли» без прогона: в нашей среде BSL не исполняется, проверка
  статическая.
