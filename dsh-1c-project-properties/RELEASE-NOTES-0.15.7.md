# 0.15.7

## Проверки кода: профиль решает состав

- `bsl_check_text` и `bsl_check_files` запрашивают у анализатора порог `hint`.
  Раньше анализатор по умолчанию отдавал только `error` и `warning`, и уровни
  `info`/`hint` до плагина не доходили: на одном модуле терялось 193 находки
  из 225. Правило `NestedFunctionInParameters` не показывалось именно поэтому.
- Порог важности из наборов убран вместе с переклассификацией уровней. Каталог
  правил перегенерирован из `rules export`: уровни теперь `error`, `warning`,
  `info`, `hint` — те же, что приходят в находках. Набор «Предупреждения и выше»
  удалён: он и был этим порогом.
- Правила, которые анализатор держит выключенными по умолчанию (15 штук),
  включаются файлом `<каталог выгрузки>/bsl-analyzer.toml`, который плагин
  генерирует под текущий профиль. В режиме stdio анализатор читает настройки
  только оттуда. Файл помечен шапкой, перезаписывается при проверке и удаляется,
  когда включать нечего; чужой файл без шапки не трогается.

- В таблице инструментов появились интернет (`web_search`, `web_fetch`), браузер
  (`browser_*`), память engram (`mem_*`) и проверки кода (`bsl_check_*`).
  `find.md` получил раздел «Вне выгрузки»; `platform.md` больше не зовёт
  несуществующий `read_page`; сборку индекса запускает человек, агент читает
  `rlm_index(action="info")`.

  старел с первого дня. У прежних раскладок файл удаляется при следующем
  развёртывании, если его не правили.
- `USER-RULES.md` — пустой шаблон из трёх заголовков, без пояснений для человека.
- В `its.md` убран счётчик «не больше двух вызовов»: ограничение по смыслу —
  тот же вопрос второй раз не задаётся.
